Building a Vector DB from Scratch with pgvector

Vector databases are at the heart of modern AI applications. In this article we build one from scratch using PostgreSQL with the pgvector extension.

Why pgvector?

pgvector slots neatly into an existing Postgres deployment. You get full-text search and vector similarity search in a single engine, which dramatically reduces operational overhead.

Prerequisites

Before diving in, make sure you have:

  • Docker 24+ installed
  • Python 3.11+
  • Basic familiarity with SQL

Setting Up the Extension

CREATE EXTENSION IF NOT EXISTS vector;
ALTER TABLE documents ADD COLUMN embedding vector(1536);
Auto (SQL)

Index the column for approximate nearest-neighbour (ANN) queries:

CREATE INDEX ON documents USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);
Auto (SQL)

Inserting Vectors

Use psycopg2 or asyncpg with the pgvector adapters:

import psycopg2
from pgvector.psycopg2 import register_vector
Auto (JavaScript)
conn = psycopg2.connect(dsn)
register_vector(conn)
with conn.cursor() as cur:
    cur.execute(
        "INSERT INTO documents (body, embedding) VALUES (%s, %s)",
        ("Hello world", [0.1, 0.2, 0.3]),
    )

Querying

Retrieve the 5 most similar documents to a query embedding:

SELECT body, embedding <=> %s AS distance
FROM documents
ORDER BY distance
LIMIT 5;
Auto (VB.NET)

Summary

pgvector is a pragmatic choice for teams already running Postgres. The extension is actively maintained, supports HNSW index types in recent versions, and integrates cleanly with Python ORMs.
